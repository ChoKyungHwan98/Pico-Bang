## 우선순위별 원인

### P1. 새 우회 함수가 갱신되지 않는 기준점을 사용한다

- `MonsterDirector.Update`는 `LayoutTeamByRoute()`를 호출한다(353행).
- `candidateOrigin` 대입은 호출되지 않는 옛 `LayoutTeam()` 안에만 있다(930행).
- 새 `TryFindDetour()`는 그 값을 중심으로 경유지를 만들고 관통도 검사한다(1140~1145행).
- 따라서 기본 실행에서는 플레이어 주변이 아니라 월드 원점 주변을 검색한다. 실제 런타임 값도 원점이다. 현재 플레이어는 원점 근처라 오차가 작지만 다른 구역에서는 크게 어긋난다.
- 수정 계약: 계획마다 하나의 NavMesh 위 기준점을 만들고, 후보 생성·관통·경로 끝점·디버그 표시가 같은 계획 스냅샷을 사용한다. 옛 함수 호출로 우회 복구하지 않는다.

### P1. 추격 상태 상한이 실제 직행 수 상한을 보장하지 않는다

- `RequestChase`는 `State.Chase`만 센다(257행).
- `LayoutTeamByRoute`는 겹침이 임계값 이하면 다른 팀원에게도 직행을 준다(1087~1100행). 직행 경로 수를 제한하는 조건이 없다.
- `MakeCutter`도 우선 `CommandPursue(..., false)`로 직행시킨다(814행).
- 현재 장면이 실제 반례다: Chase 1마리지만 직행은 3마리다.
- 수정 계약: FSM 이름과 전술 임무를 구분한다. 압박 추격 1명과 다른 경로 접근 담당을 명시적으로 배정한다. 두 번째 직행 허용 여부는 같은 접근 통로·합류시간을 기준으로 판단한다. 전역 몬스터 우선권만으로 좋은 접근 배치를 깨지 않는다.

### P1. 길 전체의 일방향 겹침률은 후속 합류를 과소평가한다

- `OverlapExcl(route, other)`는 route의 전체 유효 샘플 수를 분모로 쓴다(1415행). 짧은 경로를 긴 경로가 거의 포함해도 긴 쪽 비율은 작다.
- 위 실측에서 C가 사용하는 길은 A 경로에 전부 가깝지만 A→C는 16%여서 우회를 시도하지 않는다.
- 전체 평균은 긴 우회 구간으로 공유 통로 비율을 희석할 수도 있다.
- 수정 계약: `max(overlap(A,B), overlap(B,A))`를 최소 보정으로 사용하되 이것만으로 완료 처리하지 않는다. 마지막 공통 접근 구간의 길이, 공통 통로 진입 시각, 같은 진입구 여부를 함께 평가한다.
- 벽 너머 평행 복도와 층이 다른 길을 같은 통로로 오판하지 않도록 높이와 NavMesh 연결도 확인한다. 단순 3m 근접은 통로 ID가 아니다.
- 8m 원 내부를 모두 제외하면 실제 공유 복도도 가려질 수 있다. 접촉 직전의 짧은 수렴만 예외로 두고, 제외 반경 바깥의 마지막 진입 경로는 계속 검사한다.

### P1. 최종 접근이 감독의 정보 제한과 경로 계획을 우회한다

- `ProcessIntercept`는 finalApproach일 때 시야 여부와 관계없이 `player.position`을 0.15초마다 목적지로 준다(1200행).
- `CommandPursue`의 직행 분기는 거리와 관계없이 바로 finalApproach다(748행).
- 그 결과 감독이 `InfoLive()`로 재배치를 중단해도 개체는 현재 위치를 계속 받는다. Chase에 있는 시야 상실 속도 상한도 Intercept에는 적용되지 않는다(867~875행).
- 현재 Global/A는 44m/53m 밖에서도 '최종 접근'이며 속도 14다. 이것은 근접 마무리의 의미와 다르다.
- 수정 계약: '경유지 없음'과 '근접 마무리'를 분리한다. 정확한 직접 추격은 실제 시야·근접 조건, 비시야 이동은 감독의 유효한 힌트와 수명에 따른다. 감독의 전지적 힌트를 얼마나 허용할지는 명시적으로 남기되 개체가 무제한으로 우회하지 못하게 한다.

### P2. 팀 선발 후 경로를 나누는 순서가 포위에 불리하다

- `StartHunt`, `CleanTeam`, `ReviewTeam`은 플레이어까지 경로 길이로 팀원을 뽑거나 교대한다(417, 481, 506행).
- 같은 쪽의 가까운 둘을 먼저 고른 뒤 우회를 강요하면 큰 우회와 같은 통로 합류 사이에서 선택하게 된다.
- 수정 계약: 발견자/압박 담당을 유지하면서 나머지 가용 개체와 경로를 함께 평가한다. 전체 5마리 중 지원 2명을 고르면 최대 6개 조합이므로 팀 단위 비교를 할 수 있다.
- 선발 점수는 접근 통로 다양성, 접촉 예상시간, 공유 병목, 현재 명령 교체 비용, 구역 공백 비용을 사용한다. 멀리 떨어진 개체를 다양성만 보고 부르지 않는다.

### P2. '동시에 좁혀오기'는 문서와 구현이 다르다

- 기획안은 남은 경로에 따른 진행도 조정을 설명한다.
- 현재 `UpdateHuntSpeeds()`는 개체와 플레이어의 수평 직선거리만 사용한다(384행). 팀원 도착시간 비교나 진행도 조정은 없다.
- 수정 계약: 압박 추격자는 계속 압박한다. 협공 담당끼리만 남은 실제 경로 기준 ETA를 비교하고, 도착 편차가 큰 경우 재배치·참여 개체 교체를 먼저 검토한다. 가까운 추격자를 먼 동료 때문에 느리게 만들지 않는다.

### P2. 경로 재계획·주기적 흩어짐이 접근을 끊을 수 있다

- 매 배치에서 새 직행 경로를 먼저 검사하고, 필요할 때 새 경유지를 만든다. 현재 경로를 독립 후보로 보존하는 명시적 계약이 없다. 유지 보너스는 새 후보가 예전 경유지 근처에 생성될 때만 적용된다.
- `UpdateScatter()`는 20초 후 비추격자를 일괄 복귀시킨다(536행). 협공 직전이어도 예외가 없다.
- 수정 계약: 유효한 기존 경로를 후보에 포함하고, 경로 단절·목표가 다른 통로로 이탈·유의미한 비용 개선·기절 등 사유가 있을 때 교체한다. 재계획 자체를 줄서기 해소 성공으로 세지 않는다.
- 흩어짐은 잘못된 경로 배정을 가리는 수단으로 쓰지 않는다. 휴식 구간을 유지한다면 근접 교전 중 협공을 일괄 철수시키지 않는 조건을 둔다.

## 권장 행동 구조

새 몬스터 종류나 BT/GOAP 없이 기존 FSM을 사용하되, 감독의 임무와 이동 계획을 일관되게 만든다.

1. **압박 담당**: 발견자 또는 현재 유효하게 압박하는 1마리를 유지한다. 계속 추격해 플레이어가 멈춰 조준만 하지 못하게 한다.
2. **측면 접근 담당**: 다른 통로로 목표의 가까운 미래 이동 구간에 접근한다. 벽 뒤라면 NavMesh 경로 위에서 예측하고 월드 직선 외삽은 쓰지 않는다.
3. **앞길 접근 담당**: 플레이어 진행 경로의 다음 분기 부근을 선점할 수 있을 때 참여한다. 갈라지는 길이 없으면 불가능한 포위를 꾸미지 않는다.
4. **근접 전환**: 접근 담당이 플레이어를 보거나 유효한 근접 진입 조건을 만족하면 마무리 추격으로 전환한다. 길목 도착 후 장시간 서 있지 않는다.
5. **정보 상실**: 유효 힌트까지만 접근하고 수색·복귀한다. 제한된 힌트 추격을 허용하더라도 갱신 출처·수명·속도 규칙을 공유한다.

플레이어가 즉시 방향을 바꾸면 경로가 무효가 될 수 있다. '항상 완벽한 포위'를 보장하지 말고, 유효한 압박을 유지하며 필요한 담당만 다시 배정한다.

## 실행 순서와 완료 기준

### 1단계: 배선 결함과 계측 수정

- 기준점 갱신, 실제 직행 수 집계, 정보 제한을 우회하는 finalApproach 수정.
- 로그에는 선택 팀, 압박 담당, 각 경로의 ETA/공유 구간/전환 사유를 남긴다.
- 기존 `LayoutTeam` 및 쓰이지 않는 설정은 호출 관계를 확인한 뒤 정리한다. 옛 코드로 복귀시키지 않는다.
- 완료 기준: 원점에서 멀리 떨어진 구역에서도 우회 기준점이 목표 정보와 일치하고, Chase 상태 수와 실제 직행 수를 별도로 검증한다.

### 2단계: 팀과 경로 공동 선택

- 5마리 전체에서 지원 2명의 조합을 비교한다. 각 후보는 직행 및 제한된 우회 경로를 갖는다.
- 동일 통로 공유를 양방향으로 비교하고, 합류 지점의 예상 시간과 마지막 접근 통로를 반영한다.
- 현재 경로 유지 후보를 포함한다. 교체 보너스/쿨다운/개선 최소치로 매초 왕복하는 현상을 막는다.
- 대안이 없는 단일 통로에서는 압박 1명을 계속 보내고 나머지는 다음 유효 분기 접근 또는 유효한 다른 임무를 유지한다. 겹침 기준을 무조건 풀어 전원 직행시키는 것을 정상 포위로 기록하지 않는다.

### 3단계: 포위 압박의 흐름 조정

- 협공 담당끼리 ETA를 비교한다. 압박 담당은 동기화 대기 대상에서 제외한다.
- 근접 진입은 경로 다양성 재배정 때문에 취소되지 않게 하되, 벽 너머 직선거리만으로 잠그지 않는다.
- 스턴으로 만든 통로를 다른 개체가 즉시 메우는지 검증하고 필요할 때 짧은 재배정 유예를 둔다.
- 고정 20초 철수는 근접 압박·체력·최근 접촉 등 실제 플레이 흐름과 별개임을 로그로 드러내고 별도 튜닝한다.

## 재현 테스트

같은 시작 위치·이동 입력·난수 시드로 수정 전후를 비교한다. 실제 게임 설정과 AI 테스트 씬의 무적/이동 차이를 기록한다.

| 시나리오 | 확인할 결과 |
|---|---|
| 현재 일시정지 장면 | '직행 3'을 추격 상한 통과로 오인하지 않는다. C의 압박을 유지하면서 A/Global의 공유 접근을 식별한다 |
| 다른 구역에서 발견 | candidateOrigin이 원점에 남지 않는다 |

| 긴 경로가 짧은 경로를 포함 | 평가 순서를 바꿔도 동일 통로 충돌을 놓치지 않는다 |
| 벽 너머 평행 복도/단차 | 가깝다는 이유만으로 같은 통로 판정을 하지 않는다 |
| 분기 없는 좁은 통로 | 불가능한 우회를 강요하지 않으며 압박 담당은 계속 추격한다 |
| 플레이어가 반대로 방향 전환 | 기존 경유지를 계속 쫓거나 매초 앞뒤로 왕복하지 않는다 |
| 시야 상실, 감독 정보 만료 | Intercept가 현재 위치를 계속 읽어 추격하는 우회가 없다 |
| 두 접근자가 근접 중 20초 도달 | 시간표 때문에 갑자기 모두 복귀하는지 검증한다 |
| 스턴 후 틈으로 통과 | 실제로 통과 가능하고 충돌 복구/경로 재배정 때문에 틈이 즉시 사라지지 않는다 |

측정할 지표는 '우회 함수 호출 수'가 아니라 동일 통로에서 같은 방향으로 따라가는 지속시간, 서로 다른 통로의 동시 접근 시간, 재계획 후 실제 경로 변경, 압박 공백 시간, 스턴 돌파 성공 장면이다. 임계 수치와 목표 비율은 플레이 측정 전 확정하지 않는다.
