## 3. 복구 경위 (요약)

- 빌드가 **Mono 백엔드**라 `Assembly-CSharp.dll`에서 스크립트 220개가 `[Header]`까지 살아있는 상태로 복원됨 (주석만 소실)
- AssetRipper 산출물은 패키지를 `Assets/Plugins`의 DLL로 박아두므로, 정식 패키지로 교체하며 **m_Script GUID를 재매핑**함 (94건 + 셰이더 참조 45건, 전부 무손실)
- 기법 상세는 메모리 `unity-dll-guid-remap-technique` 참고

## 4. 완료된 작업

### 감각 / 조작
- **마우스룩 버그** — 마우스 델타에 `Time.deltaTime`을 곱하고 있어 회전량이 프레임 시간의 제곱에 비례했다 (144fps 0.104 / 60fps 0.250). 제거하고 `GameSettings.MouseSensitivity`로 통일
- **리지드바디 보간** 켬 + vSync 켬 + MSAA 4x
- **순간이동 처리** — 보간을 켜면 `transform.position`만 바꿔선 안 된다. `PlayerController.TeleportTo()`가 `rb.position`과 `Physics.SyncTransforms()`까지 처리
- **달리면서 사격** — `Upper Layer`에 아바타 마스크가 없어 상체 애니메이션이 온몸을 덮어썼다. `UpperBody.mask` 생성(팔·손·손가락·손IK만 활성), Shoot 상태 속도 1.45

### 시스템 (기획 구현)
- **`NoiseSystem`** — 소음 전파. 발사음(플레이어 위치, 30m) / 과녁 파괴음(과녁 위치, 45m) 분리
- **`MonsterDirector`** — 감독. 플레이어 위치를 알지만 무리에게는 **개체별로 다른 방향의 흐린 지점**만 보낸다. 발견은 각 몬스터의 감각이 한다. 씬 배치 불필요(자동 생성), 호출 규격은 전역 몬스터의 인스펙터 값을 따름
  - 이전의 포위 대형은 테스트에서 "4마리가 비엔나 소시지처럼 줄줄이 따라옴"이 나와 폐기. 원인 분석은 `시스템설계_몬스터AI.md` 2장
- **`MonsterAI`** — 플랫 FSM 5상태(`Surround` 삭제). 청각을 역할별 비대칭으로(전역 = `hearingRange`, 구역 = × `zoneHearingScale`). 소리는 부정확한 위치만 준다
  - 버그 수정: 수색 중 새 지점을 받아도 무시되던 것, `investigateRushScale`이 매 프레임 덮어써지던 것
- 하드코딩 수치 전부 인스펙터 노출. 죽은 필드 `contactDamage` → `contactDamageHearts`(실제 동작)

### 버그 수정
- **BGM 미재생** — `SoundManager`의 코루틴 경합. 페이드아웃이 마지막에 `Stop()`을 불러 방금 켠 곡을 껐다. 단일 코루틴으로 직렬화
- **초기화 누락** — `IGameResettable`이 선언만 되고 아무도 호출하지 않았다. `GameFlowManager`가 호출하도록 연결
- **크로스헤어 타이밍** — 카운트다운 전에 켜지던 것을 `isGameRunning = true` 시점으로 이동

### 연출
- `StunSparkEffect` — 몬스터 피격 전기 아크 (에셋 없이 코드로 생성)
- `Projectile` + `BurstVfx` — 판정은 즉시, 연출만 지연. 발사체 속도 135
- `Target` — 원형 5단 과녁으로 재구성 + 파괴 연출(부풀었다 회전하며 수축)
- `CrosshairFx` — 발사 시 벌어지고 명중 시 색이 튄다

### UI
- **잘난체** 적용 (동적 아틀라스). `Assets/Font/Jalnan2 SDF.asset`
- **설정 메뉴** — 전체음량/배경음/효과음/마우스감도/전체화면/기본값. `GameSettings`가 PlayerPrefs에 저장
- 홈 화면 재구성 — 전용 카메라 앵글, 좌측 컬럼 정렬, 조작 안내
- 게임오버/클리어 화면 — 전체 화면 불투명 처리(테두리 비침 해결) + 버튼 스타일 통일

### 사용자가 직접 잡은 값
- **홈 표정**: `mouth_I 66` + `Angry 43.4` (도야가오)
- **시작 위치**: `(-0.1251164, 0.07844073, 0.004084607)` / 회전 Y `8.347`
- **홈 카메라**(`IntroCamPos`): `(0, 1.267, 0.678)` / 회전 `(0.989, 165.636, -4.629)`

## 5. 미해결

### 속도선 (`FS_Speed`)
현재 **렌더러 피처 비활성화** 상태. 머티리얼·텍스처·셰이더는 보존.

- 원본은 **Pico Chan 에셋**에 딸려 있던 Shader Graph (사용자 확인)
- 텍스처 `Assets/Texture2D/CNoise.png`는 생존
- 머티리얼에 원본 프로퍼티가 남아 있음: `_Tiling(3,9)`, `_Mask_Size 0.56`, `_Mask_Contrast 1`, `_Smoothness 4`, `_Speed 1`, `_Color(2,2,2) HDR`
- Claude가 이 값으로 재현을 시도했으나 결과가 원본과 달라 폐기
- **해결책**: Pico Chan 에셋 패키지를 다시 임포트해 `FS_Speed` 그래프를 꺼내오는 것.
  Package Manager → My Assets에서 이름 확인 필요
- **현재 (2026-09-11)**: **Mirza Beig "Anime Speed Lines"** 풀스크린 셰이더 (사용자 지정, Unlicense — `Assets/Shader/AnimeSpeedLines/LICENSE.txt`)
  - 원본의 URP 연결 스크립트(`CustomRenderPass`)는 URP 17에서 제거된 API(`RenderTargetHandle`, `cameraColorTarget`)를 써서 가져오지 않았다
  - 셰이더 계산만 `AnimeSpeedLines_URP.shader`로 옮기고 입력을 `_BlitTexture`로 교체 → URP 기본 `FullScreenPassRendererFeature`(PC_Renderer 2번째, FS_Speed 자리)에 연결해 **켬**
  - 머티리얼 `Assets/Material/AnimeSpeedLines.mat` (원본 데모 값 그대로). 강도 프로퍼티를 `_FullscreenIntensity`로 두어 `PlayerController`의 기존 달리기 훅이 그대로 구동
  - 씬 `PlayerController.speedEffectMaterial`도 새 머티리얼로 교체. FS_Speed 머티리얼은 참조 0건이 됐지만 원본 복구 대비로 남겨둠
  - 파티클 속도선(`SprintSpeedLines.cs`, `Resources/SpeedLines.prefab`)은 프로젝트에서 뺐다. 백업: 세션 scratchpad `backup-particle-speedlines/`
- (폐기) **임시 대체 (2026-09-10)**: Arcade Racing Kit(Ilumisoft)의 **Speed Lines를 그대로 이식** (사용자 지정).
  - `Assets/Resources/SpeedLines.prefab` — 킷 씬(`Downloads\에셋\...\Example.unity`)의 `Speed Lines > Particle System`을 YAML 그대로 옮김.
    바꾼 것: 머티리얼 2칸(입자·트레일 둘 다 내장 기본 → URP `ParticlesUnlit.mat`, 안 바꾸면 분홍색), 쓰이지 않는 외부 참조 1건 끊음. 파티클 수치는 무수정
    ⚠ **선의 정체는 트레일이다.** 입자 자체는 0.02 크기의 점이고, 눈에 보이는 선은 트레일 모듈이 그린다.
    렌더러 두 번째 머티리얼(트레일용)을 비우면 선이 통째로 사라진다 — 실제로 한 번 이 실수로 안 보였음
  - `SprintSpeedLines.cs` — 킷 `SpeedLines.cs`의 동작(카메라 반대쪽을 수평으로 바라보기, 초당 50개) 재현
  - **카메라 보정**: 킷은 카메라 FOV 40°·차 뒤 4.5m 기준이라, 그대로 붙이면 Pico-Bang 카메라(FOV 60°, 플레이어 1m 뒤)에서는
    고리가 화면 밖에 생겨 거의 안 보였다. 킷 카메라 배치를 카메라 기준으로 재현하고, **깊이 방향만** k = tan(30°)/tan(20°) ≈ 1.59로 나눈다
    (발생 거리·입자 속도·원뿔 길이). 반지름·굵기는 그대로 → 화면상 각도와 픽셀 굵기가 킷 화면과 같다
  - **이 게임용 튜닝** (피드백 3회: 잘 안 보인다 → 더 많이 더 빠르게 → 더 많이 더 잘 보이게, 아래가 안 보임):
    굵기 0.02→0.1, 초당 50→400, 속도 ×1.8, 고리 안쪽 비움(`ringThickness 0.35`, 조준점 보호), 꼬리 투명 페이드, 흰색 α1.
  - **방향 반전 (4차)**: 킷은 선이 카메라에서 멀어지는 방향(수평)이라, 정면에서 보면 선 끝이 겹쳐 점으로 뭉개지고
    위를 올려다볼 때만 선으로 보였다(사용자 스크린샷으로 확인). → 화면 가운데 멀리서 생겨 카메라 쪽으로 날아와
    가장자리로 빠져나가게 뒤집고, 카메라 방향(상하 포함)을 그대로 따르게 함. 굵기 0.04(가까운 쪽이 굵어 보이므로),
    `effectScale 0.2`, `endDistance 2.5`. 이 시점부터 킷에서 남은 것은 원뿔 발생 방식·트레일 구조·수명뿐
  - (이전) **축소 + 눈높이 중심**: 킷 고리(반지름 4m, 중심이 카메라 3.2m 아래)는 아래쪽 절반이 바닥에 파묻혀 가려졌다.
    효과 전체를 `effectScale 0.25`로 균일 축소(화면상 모습은 동일, 실제 크기만 작아짐 — `scalingMode Hierarchy`)하고
    고리 중심을 카메라 눈높이로 올림(`centerHeight`로 미세 조정)
    프리팹은 킷 원본 유지, 값은 `SprintSpeedLines` 인스펙터에서 덮어씀
  - `PlayerController`가 `runThreshold`(8) 이상일 때 강도를 올린다. 씬 수정 없이 `Awake`에서 자동 부착
  - 그 킷의 나머지 속도 연출(`SpeedPostProcessingEffect`)은 Post Processing v2 기반이라 URP에서 쓸 수 없다
  - ⚠ 배포 전 킷 라이선스 확인 필요 (역추출본에서 가져옴 — 정식 패키지를 받아 교체하는 편이 깨끗하다)
  FS_Speed 원본을 되찾으면 둘 다 켜둘지, 속도선을 끌지 결정할 것

## 9. 포트폴리오 관점 메모

사용자는 **전투/시스템 기획자** 지망. 이 프로젝트를 포트폴리오로 쓴다.
