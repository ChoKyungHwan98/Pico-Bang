## 1. 사용자 목표와 범위

### 1.1 사용자 목표

> 제한시간 안에 빠르게 움직이면서, 좁혀오는 몬스터의 포위망에서 빈틈을 찾아 과녁을 부수고 탈출한다.

구체적 요구:

1. 과녁을 부술 때마다 몬스터가 플레이어의 위치 정보를 다시 얻는다.
2. 과녁을 찾아 돌아다니는 동안 몬스터가 오랫동안 없다는 느낌을 줄인다.
3. 여러 마리가 한 줄로 같은 복도를 따라오는 현상을 줄인다.
4. 시야를 끊거나 레이저로 기절시켜 포위망에서 빠져나갈 수 있다.
5. 구역 몬스터 4마리는 같은 FSM을 사용한다. 전역 몬스터 1마리는 넓은 순찰·지원 역할을 가진다.
6. 실제 플레이 경험과 AI 판단을 함께 보여주는 포트폴리오 증거를 만든다.

### 1.2 이번 구현 기준

- 몬스터 총 5마리 유지. 직접 추격 최대 2마리. 인위적으로 항상 2마리를 채우지는 않는다.

- 현 8방향 자동 차단 후보를 유지하며 실제 경로, 도착시간, 관통, 경로 겹침을 기준으로 배정한다.

- 실제 게임 씬에 켜고 끌 수 있는 관찰·촬영 모드를 추가한다. 별도의 복제 게임 씬은 만들지 않는다.
- 기존 `ShooterInGame_AITest`는 원인 확인용 실험 씬으로 유지한다.

### 1.3 이번 범위에서 제외

## 3. 정보 규칙: AI가 무엇을 아는가

### 3.1 세 가지 정보

| 정보 | 발생 조건 | 위치 의미 | 사용 |
|---|---|---|---|
| 목격 | 개체가 시야 판정 통과 | 목격 시점의 플레이어 위치 | 직접 추격 허가, 차단·수색 |
| 과녁 경보 | 플레이어 사격으로 과녁 파괴가 최초 확정 | 그 사격의 발사 시점 위치 | 제보 확인, 길목 선점, 사냥 관심 갱신 |
| 일반 소음 | 발사 등 | 소리 발생 위치 | 범위 내 개체의 조사 |

정보에는 `eventId`, `sourceKind`, `observedAt`, `receivedAt`, `position`, `reporterId/shotId`를 둔다. 시각은 같은 게임 세션의 게임 시계 기준이다. UTC는 파일 메타데이터용이다.

- 신선한 목격이 있으면 더 오래된 경보로 덮어쓰지 않는다.
- 경보는 이동 방향·속도를 제공하지 않는다. 멀리 떨어진 연속 사격 위치의 차이로 실시간 속도를 만들지 않는다.
- 목격이 없을 때 경보로 기준점이 바뀌면 예전 목격 방향을 새 기준점에 붙이지 않는다. 방향은 미상으로 둔다.
- 지속 목격에서 얻은 방향은 목격 상실 후 동결한다. 최신 위치·Rigidbody 속도를 다시 읽지 않는다.
- 정보 유효기간은 `observedAt` 기준. 늦게 도착한 발사체가 오래된 사격 정보를 새 정보처럼 부활시키지 않는다.
- 관찰·기록 도구는 실제 위치를 읽어도 되지만, 그 데이터를 AI 판단으로 전달하지 않는다.

### 3.2 발사부터 경보까지의 계약

1. 발사 순간 불변 `ShotContext` 생성: shotId, 발사 위치, 발사 시각.
2. 발사체 콜백과 즉시 판정 경로 모두 동일한 context를 `ApplyHit`까지 전달.
3. 과녁의 최초 파괴 처리 성공 시에만 context를 사용해 경보 1회 발행.
4. 점수·파괴·경보가 중복 발생하지 않도록 기존 `isDestroyed` 가드를 공유.
5. 플레이어 사격이 아닌 테스트·다른 호출의 파괴는 위치 context가 없으면 경보를 생략하고 이유를 로그로 남긴다. 현재 플레이어 위치를 대신 채우지 않는다.
6. 기존 과녁 위치 파괴음은 효과·주변 반응용으로 유지하되, 같은 사건의 낮은 우선순위 소음이 경보 명령을 덮어쓰지 못하게 한다.
7. `Target.OnHit`의 기존 호출처를 모두 찾아 호환 처리한다. 기존 점수·포탈·파괴 연출을 변경하지 않는다.

경보는 맵 전체 Director에 전달하는 명시적 게임 규칙이다. 경보 신호와 짧은 반응음을 추가해 플레이어에게 알려준다. 경보를 받았다는 이유만으로 보지 못한 개체를 Chase로 전환하지 않는다.

## 4. 맵 데이터와 순찰

### 4.1 현재 결정: 별도 지정 데이터는 만들지 않음

이 단계에서는 `AITacticalMap`, 수동 길목, 지정 순찰 경로를 만들지 않는다. 하위 작업자는 아래 폐기안을 구현하거나 씬에 좌표를 추가하지 않는다. 우선 현재 구역 데이터와 8방향 자동 후보가 실제 NavMesh 경로를 올바르게 쓰도록 검증한다.

### 4.1-A 폐기된 확장안(참고 전용)

향후 자동 후보 방식의 한계가 플레이테스트로 확인될 때만 재검토할 수 있었던 안이다.

- 구역 ID와 연결 관계.
- 구역별 순찰 지점 및 연결 순서. 출입구·과녁 활동 구간·다른 출구를 포함.
- 전역 몬스터의 구역 간 순찰 경로.
- 길목 ID, 위치, 해당 구역, 연결하는 두 구역/분기, 같은 통로를 식별하는 corridorId.
- 해당 길목에서 확인할 방향, 통과 판정용 gate의 폭·방향.
- 점프·단차를 포함한 실제 이동 가능 여부.

좌표는 스크린샷에서 환산하지 않는다. Unity 씬과 NavMesh를 확인하여 배치하고 Scene 뷰에서 라벨·연결선을 검토한다. ID는 로그에서 재현 가능하도록 고정하며 런타임 InstanceID만 사용하지 않는다.

### 4.2 현재 순찰 규칙

- 구역 개체는 현재 zoneCenter/zoneRadius 안의 NavMesh 목적지를 사용한다. 최초 목적지는 `Start`에서 반드시 한 번 선택한다.
- 전역 개체는 `useGlobalNavMesh = true`로 전체 NavMesh 정점 중 목적지를 선택한다.
- 과녁이 런타임 배치되더라도 남아 있는 과녁을 정확히 따라가는 기능은 추가하지 않는다. 우선 과녁이 배치되는 활동 구간을 순찰한다.
- 일반 지원은 자기 구역·인접 구역까지만 허용한다. 전역은 제한 없음. 직접 목격 추격은 기존 추격 범위 규칙을 별도로 적용한다.
- 명령 종료 시 구역 개체는 자기 zoneCenter/zoneRadius 순찰로, 전역 개체는 전체 NavMesh 순찰로 복귀한다.
- 데이터 누락·연결 실패는 오류로 표시한다. 임의 월드 원점 또는 플레이어 위치를 목적지로 삼지 않는다.

## 5. Director 명령 규칙

### 5.1 명령 우선순위

기절·게임 종료 > 직접 목격에 대한 추격 허가 > 유효한 차단/제보 명령 > 일반 소음 조사 > 순찰.

정보 수신과 행동 변경은 분리한다. 차단 중에도 경보를 수신하되 즉시 매번 목적지를 바꾸지 않는다. 기절 개체도 공유 정보에는 접근할 수 있지만 움직이지 않는다.

명령에는 orderId, 개체 ID, 종류, 목적지/길목 ID, 근거 eventId, 발행 시각, 만료 시각, 해제 이유가 있어야 한다. 별도 Role 상태 계층을 만들지 않는다.

### 5.2 상태별 배치

| 상황 | 배치 기준 |
|---|---|
| 유효 경보만 있음 | 가장 빨리 도착 가능한 1마리에게 사격 위치 조사. 다른 1마리에게 인접 길목 확보. 나머지 순찰 |
| 직접 목격 발생 | 발견자가 추격 허가 요청. 구역 발견 시 차단 목표 1마리, 전역 발견 시 최대 2마리 |
| 추가 개체 발견 | 추격 상한 2 적용. 허가 안 나면 유효한 다른 길목 확보 또는 기존 명령 유지 |
| 전원 시야 상실 | 0.5초 유예 후 마지막 정보 기준 분산 수색. 새 근거 없이는 수색 기준점 이동 금지 |
| 새 경보 수신 | 정보 신선도 비교 후 조사 기준 갱신. 다른 구역으로 넘어갔으면 불필요한 차단 해제 |
| 유효 정보 만료 | 명령 해제 후 구역 순찰 복귀 |
| 기절 회복 | 최신 정보와 추격 허가를 다시 확인. 만료된 명령 복원 금지 |

- 추격 상한이 찼다는 이유로 차단 목표 수를 계속 더하지 않는다. 기존 `demoted.Count` 가산 방식은 목표 수 상한과 일치하게 정리한다.
- 직접 추격 상한 2는 진입 순간에도 지킨다. 기절 복귀·전역 우선 교대·동일 프레임 발견도 포함한다.
- 적절한 후보가 없으면 차단 수를 억지로 채우지 않는다. 이유를 기록하고 순찰 또는 유효한 기존 명령을 유지한다.
- 전역이 경보를 들었다는 이유만으로 목격 사냥의 큰 포위로 격상하지 않는다.

### 5.3 차단 후보 선정

1. 최신 정보 위치에서 월드 8방향으로 `cutCandidateMaxDistance`만큼 뻗고 NavMesh 위에서 갈 수 있는 끝점을 찾는다.
2. 너무 짧은 후보는 버리고 서로 가까운 끝점은 더 멀리 뻗은 한 점으로 합친다.
3. 몬스터-후보 조합마다 완전한 NavMesh 경로를 계산한다. 경로가 없으면 유한한 벌점을 주지 않고 제외한다.
4. 몬스터 경로가 마지막 정보 위치의 `crossingAvoidRadius` 안을 관통하면 제외한다.
5. 플레이어 예상 도착시간도 정보 위치→후보의 완전한 NavMesh 경로 길이 / 11로 계산한다. 실제 숨은 위치는 읽지 않는다.
6. 몬스터 도착시간은 실제 경로 길이 / 해당 개체의 `TrackSpeed`다. 플레이어보다 `cutLateTolerance`를 넘게 늦으면 제외한다.
7. 다른 사냥 개체의 현재 위치+예정 경로 또는 이번 배치에서 먼저 선택한 경로와 `routeOverlapLimit`보다 많이 겹치면 제외한다.
8. 남은 조합은 막힌 방향과의 각도, 도착시간, 기존 명령 유지 보너스로 선택한다. 기존 차단점이 3m 안이면 유지 보너스를 주어 1초마다 흔들리지 않게 한다.
9. 유효 조합이 없으면 차단 수를 억지로 채우거나 자기 위치를 목적지로 주지 않는다. 기존 추격자의 자리를 비우지 못했으면 새 추격자도 허가하지 않는다.

주의: 자동 8방향 끝점은 실제 맵의 의미 있는 출구를 항상 대표하지 않는다. 다른 순찰 개체·플레이어 판단·맵 형상에 따라 빈틈이 달라진다. 포트폴리오에서 '탈출 보장'이라고 표현하지 않는다. 런타임 탑뷰에서 반복적으로 엉뚱한 벽면이 선택될 때만 지정 길목 방식을 다시 검토한다.

### 5.4 명령 유지와 실패 처리

- 도착 전 목적지를 유지한다. 도착 후 대기 기본 4초. 발행 후 최대 12초에서 만료한다.
- 0.5초마다 상황을 평가해도 다음 사유가 아니면 목적지를 바꾸지 않는다: 경로 실패, 다른 구역의 새 근거, 추격 교대, 기절, 만료.
- 위치의 작은 변화만으로 같은 구역 차단점을 재선정하지 않는다.
- 길목 대기 중 가까이 보이면 기존 8m 기준으로 추격 허가·교대 판단. 멀리 보이면 보고만 한다.
- 이동 중 2초간 경로 진행이 없으면 경로를 한 번 재평가하고, 여전히 실패하면 해제·로그. 정지 대기·기절·일시정지 시간은 정체 판정에서 제외한다.
- 차단 몬스터가 기절하면 그 길목을 2초간 새 개체로 재예약하지 않는다. 다른 개체의 자연스러운 직접 목격 반응을 강제로 막지는 않는다.
- 수색 후보가 부족하거나 경로가 끊겼으면 배정 안 된 개체도 명시적으로 해제한다. Director 기록만 지우고 옛 FSM 명령을 남기지 않는다.

## 6. 접촉 빈도와 튜닝

### 6.1 처음 적용할 값

| 값 | 기준 | 분류 |
|---|---:|---|
| 총 몬스터 | 5 | 구현 고정 |
| 직접 추격 상한 | 2 | 구현 고정 |
| 플레이어 걷기/달리기 | 5 / 11 | 기존 유지 |
| 구역 추격/전역 추격 | 10 / 11 | 기존 유지 |
| 구역 순찰 | 현재 개체별 6~7 유지 | 초기 기준 |
| 전역 순찰 | 8 | 기존 유지 |
| 명령 이동 속도 | 해당 개체 추격 속도 | 구현 기준 |
| 전원 시야 상실 유예 | 0.5초 | 튜닝 가설 |
| 정보 유효기간 | 목격·경보 모두 8초 | 튜닝 가설 |
| 차단 평가 주기 | 0.5초 | 튜닝 가설 |
| 도착 후 차단 대기 | 4초 | 튜닝 가설 |
| 명령 최대 수명 | 12초 | 튜닝 가설 |
| 선점 여유시간 | 1초 | 튜닝 가설 |
| 사격 간격/총 기절 | 1.5초 / 3초 | 기존 유지 |

Director 설정은 공용 `MonsterDirectorSettings` ScriptableObject 한 곳으로 모은다. 기존 전역 개체 필드에서 실제 값을 이관하고, 실게임과 테스트 씬이 같은 asset을 참조하게 한다. 개체 감각·속도는 기존 MonsterAI 설정을 유지한다. 이관 중 구값과 신값을 동시에 읽지 않는다.

### 6.2 빈 구간 대응

- 경보 반응은 매 파괴마다 정보를 갱신하되, 동일 명령을 매번 재시작하지 않는다.
- 경보 후 5초간 새 직접 목격이 없고 정보가 유효하면, 기존 조사 개체의 도달 가능성과 경로 진행을 점검한다.
- 조사자가 기절·실패 상태면 다른 가용 개체와 교대한다. 전원 실패하면 로그를 남긴다. 실제 플레이어 위치로 보내서 성공시킨 척하지 않는다.
- 유효 정보가 없으면 지정 순찰만 수행한다. 무정보 상태에서 플레이어를 찾아내는 보정은 넣지 않는다.
- 몬스터가 물리적으로 도착할 수 없는 거리에 있으면 즉시 접촉을 보장할 수 없다. 이 문제는 순찰 배치·맵 연결·이후 인원 실험으로 해결한다.

튜닝 순서: 순찰 동선 → 반응 개체 선정 → 차단 성공 → 속도 0.5 단위 조절 → 마지막에 인원 추가 검토. 한 실험에서 한 축만 바꾼다. 6마리 실험은 기본 구현 완료 후 별도 제안으로 남긴다.

## 7. 포트폴리오 관찰 모드

### 7.1 씬과 화면

새 복제 씬 대신 `ShooterInGame`에 기본 비활성 관찰 도구를 둔다. `AITestDebug`를 실게임에 붙이지 않는다. 필요한 선·마커 렌더링만 재사용 가능한 별도 표시 코드로 추출한다.

촬영 기본 1920×1080:

- 좌측 약 70%: 실제 플레이 카메라와 게임 UI.
- 우측 약 30%: 동기화된 탑뷰 맵, 간단한 범례, 최근 사건 3줄.
- 탑뷰는 **같은 씬의 같은 개체**를 RenderTexture로 촬영한다. 별도 시뮬레이션·복제 몬스터를 두지 않는다.
- 세로로 긴 맵을 자르지 않고 맞춘다. 두 화면에 같은 sessionId와 게임 경과시간을 표시한다.
- 기본 화면에서 전체 청각 원·시야 부채꼴·모든 후보 선은 끈다. 상세 디버그 토글에서만 보인다.

표시 항목: 플레이어, 개체 ID, 실제 상태(추격/차단/수색/기절/순찰), 선택 길목, 마지막 목격/경보 위치, 정보 나이, 최근 3초 이동 궤적. 색과 글자를 함께 사용한다.

### 7.2 절대 바꾸면 안 되는 것

- 실제 이동·사격 입력, 카메라 조작, 충돌, 체력, 제한시간, 점수, 과녁, 포탈.
- timeScale, 몬스터 의사결정, 실제 사운드 설정.
- UI가 입력을 가로채거나 탑뷰 카메라가 AudioListener를 추가하는 동작.
- 표시용 레이어를 시야·충돌 판정에 섞는 것.

관찰 모드를 끄면 원래 화면으로 복귀한다. RenderTexture·카메라·이벤트 구독을 정리한다. 탑뷰 숨김 상태에서도 게임 규칙이 동일해야 한다. 개발용 화면과 포트폴리오용 화면을 같은 토글로 무적 처리하지 않는다.

F8: 관찰 레이아웃, F9: 상세 선 표시, F10: 수동 북마크를 기본 후보로 사용하되 기존 키 충돌을 먼저 검사한다. 재매핑 가능하게 한다. 도구 자체에 영상 인코더를 만들지 않고 외부 화면 녹화를 사용한다.

## 8. 기록과 지표: 사실과 해석을 구분한다

### 8.1 저장 형식

세션마다 `Application.persistentDataPath/AIReports/<sessionId>/`에 기록한다.

- `session.json`: 코드 commit ID(가능하면), 설정 버전, 씬, 실제 파라미터, 시작 배치·과녁 배치, random seed(통제한 경우), 빌드/Editor, 실험 조건, 시작 시각.
- `events.jsonl`: 사건별 시각·ID·정보 근거·상태 전이·명령·해제 이유.
- `samples.jsonl`: 5Hz 위치·상태·목적지·최신 정보 age·개체별 시야 여부·게임 카메라에서의 개체 노출 여부. 프레임별 파일 쓰기 금지, 버퍼 사용. 가시성 지속시간과 gate 통과는 프레임마다 내부 평가하고 사건 시각을 저장한다. 5Hz 샘플만으로 짧은 통과를 놓치지 않게 한다.
- `annotations.json`: 수동 검토 구간, 판정, 이유, 영상 타임코드.
- `summary.json`: 아래 정의의 건수·시간·분모. 없는 값은 0으로 꾸미지 않고 null/미측정으로 표시.

저장 실패는 게임을 중단시키지 않고 경고·기록 실패 표시. 초기화 시 새 세션을 만들고 이전 사건을 섞지 않는다. 관찰 모드가 직접 AI 명령을 호출하지 않도록 참조 방향을 제한한다.

필수 사건: ShotFired, TargetDestroyed, AlarmReceived, SightingAcquired/Lost, OrderIssued/Released, CutArrived, GateCrossed, StunStarted/Ended, HuntEnded, PlayerDamaged, EscapeCompleted, ManualBookmark.

### 8.2 경로 변경은 자동으로 원인을 확정하지 않는다

플레이어가 방향을 틀었다는 사실만으로 '차단을 보고 피했다'고 셀 수 없다. 과녁을 찾거나 벽을 피한 것일 수 있다.

자동 후보 검출:

1. 차단 명령을 수행 중인 몬스터가 게임 카메라 화면 안에 있고, 플레이어 쪽에서 장애물에 가리지 않는 상태가 0.3초 이상 지속.
2. 그 전 1초 동안 수평 속도 3m/s 이상이며 이동 방향이 안정적(방향 편차 20도 이하).
3. 노출 후 2초 안에 이전 이동 방향 대비 45도 이상 바뀌고 새 방향 이동이 0.5초 이상 지속.
4. 같은 개체·orderId의 후보를 3초 내 중복 집계하지 않는다.

이는 화면 노출·방향 전환 후보일 뿐 사람의 인지 판정이 아니다. 별도 Player-view 가시성 검사를 쓰고 MonsterAI.CheckSight를 대신 쓰지 않는다.

수동 영상 검토에서 기존 진행 방향, 차단 몬스터 노출, 다른 통로 선택을 확인한다. 가능하면 플레이어의 짧은 사후 설명을 첨부한다. `확인 / 불명확 / 제외`로 분류한다. 포트폴리오에는 '차단 노출 후 경로 변경 후보 N건, 영상 검토 확인 M건'처럼 쓴다. 자동 수치에 인과관계 이름을 붙이지 않는다.

### 8.3 시야 상실·탈출

- **시야 단절 사건:** 마지막 시야 보고 후 0.5초 동안 전원이 플레이어를 보지 못함.
- **추격 해제 구간:** 시야 단절 이후 5초 동안 재목격이 없고, 구간 종료 시 Chase 개체 0. 새 경보가 생기면 `새 경보 있음`으로 별도 표시한다.
- **사냥 종료:** 최신 유효 정보 만료로 Director가 실제 종료한 사건. 시야 단절·추격 해제와 별도 집계한다.
- **기절 후 통과 후보:** 차단 개체 기절 시작 후 3초 안에 플레이어가 해당 gate를 반대편으로 통과. 같은 기절 사건당 1회.
- **기절을 활용한 탈출 확인:** 통과 후보와 그 뒤 5초를 영상으로 보고, 기절이 길을 여는 데 기여했는지 수동 판정. 단순 스턴 명중 수와 혼합하지 않는다.

GateCrossed는 gate 평면의 부호 변화 + 폭 내부 통과를 기준으로 한다. 순간이동·재시작·테스트 위치 이동은 제외한다. 유효 gate가 없는 장면은 자동 집계하지 않고 수동 북마크로 남긴다.

### 8.4 접촉·공백 지표

- 경보 반응 지연: 경보 수신→첫 유효 명령 발행. 이것을 플레이어가 위협을 느낀 시간이라고 부르지 않는다.
- 경보 후 화면 노출 지연: 경보→게임 카메라에 몬스터가 0.3초 이상 노출된 최초 시각. 다음 경보 전에 없으면 미노출/관찰 종료로 기록한다.
- 몬스터 화면 미노출 최장 시간, 전원 미목격 최장 시간은 각각 측정한다.
- 발소리·반응음을 '존재감' 지표에 포함하려면 실제 청취 가능 여부를 기록해야 한다. 음원 재생 호출만으로 들었다고 판정하지 않는다. 초기에는 영상·오디오 수동 검토로 남긴다.
- 차단 성공 후보: 몬스터가 예약 길목에 플레이어보다 먼저 도착했는지. 예약 횟수와 도착 횟수를 구분한다.
- 상태별 체류시간, 동일 통로 추격·차단 중첩시간, 도달 불가 명령 수, 경보당 참여 개체 수를 보조 지표로 기록한다.

## 9. 재현 시나리오와 완료 판정

테스트 배치·과녁 위치·설정·시작 지점을 저장한다. seed만 같다고 물리·입력까지 결정적으로 재현된다고 주장하지 않는다.

| ID | 절차 | 반드시 확인할 결과 |
|---|---|---|
| T01 | A에서 발사 후 B로 이동, 늦게 과녁 명중 | 경보는 A와 발사 시각. B를 읽지 않음 |
| T02 | 같은 과녁에 발사체 2개 도착 | 파괴·점수·경보 각각 최초 1회 |
| T03 | 최신 목격 후 더 오래된 사격의 경보 도착 | 최신 목격이 유지됨 |
| T04 | 아무도 안 보는 곳에서 과녁 파괴 | 조사 명령 발생, 시야 없는 Chase 진입 없음 |
| T05 | 세 개체가 같은 프레임에 발견 | 직접 Chase 수가 어떤 시점에도 2 초과 안 함 |
| T06 | 벽 뒤로 이동 후 반대로 도망 | 정보 위치 동결. 새 근거 없이 실제 위치를 따라갱신하지 않음 |
| T07 | 꺾인 복도에서 길목 차단 | 지정 길목 선택, 완전 경로, ETA 조건 충족, 같은 진입 통로 중복 방지 |
| T08 | 연결 끊긴 길목·모든 후보 불합격 | 불가능 명령 미발행, 명확한 제외 이유, 정상 순찰/기존 명령 유지 |
| T09 | 같은 구역에서 연속 사격하며 이동 | 정보는 갱신, 차단 목적지는 사유 없이 매번 교체되지 않음 |
| T10 | 차단 개체를 기절시키고 gate 통과 | 통과 후보 1건, 짧은 재예약 유예, 회복 후 최신 판단 |
| T11 | 수색 후보 부족 또는 기절 중 사냥 종료 | 옛 명령 잔존·회복 후 만료 명령 부활 없음 |
| T12 | 관찰 모드 켜고 끄며 일반 플레이 | 이동·피격·시간·사격·과녁·포탈 동일, UI/AudioListener/리소스 이상 없음 |
| T13 | 재시작·씬 전환·Play Mode 종료 | 세션/명령/이벤트 구독/표시 리소스 정상 정리 |
| T14 | 몬스터 없는 곳에서 일부러 급회전 | 차단 경로 변경 후보로 기록되지 않음 |

수치 가설 검증은 기능 통과와 구분한다:

- 과녁 파괴 후 1초 내 경보 피드백을 목표로 하되 UI·사운드 전달도 실제 확인한다.
- 5~10초 내 접근 위협, 10~15초 이상의 긴 무존재 구간 감소는 경험 목표 가설이다. 모든 위치에서의 보장 조건으로 사용하지 않는다.
- 변경 전·후 각각 동일 조건으로 최소 5회 측정한다. 샘플이 작으므로 통계적 일반화·유의미한 개선 단정 금지.
- 통제된 시나리오와 자유 플레이 5분을 분리한다. 가능한 경우 다른 플레이어의 자유 플레이도 별도로 기록한다.
- 표에는 실행 수, 발생 기회 수, 확인 건수, 미발생·불명확 건수, 실패 사례를 함께 기록한다.

## 10. 구현 단계와 산출물

### P0 — 기준선 보존

현재 코드 revision·씬 설정·배치를 기록한다. 변경 전 촬영을 원하면 최소 관찰/기록 도구를 먼저 연결한 상태에서 기준선을 확보한다. 기존 AI 테스트 화면의 무적 실험 결과를 일반 플레이 기준선으로 사용하지 않는다.

완료: 기준선 설정·영상 또는 미촬영 사유, 현재 오류 목록, 기존 사용자 변경 목록.

### P1 — 기록·관찰 기반

제안 파일: `AIObservationOverlay.cs`, `AITelemetryRecorder.cs`, `AIObservationEvents.cs`. 실제 네임스페이스·어셈블리 구조를 먼저 확인한다. 기본 비활성으로 실게임 연결, 시각·ID·북마크·두 카메라부터 구현한다. 사건 없는 지표를 임의 계산하지 않는다.

완료: T12~T13의 관련 부분. 한 세션 로그와 동기화 화면 확인. 그 다음 기준선 촬영. P5의 후보 검출기를 아직 만들지 않았어도 비교에 필요한 위치·상태·카메라 노출 원시 기록은 이 단계에서 남긴다. 변경 전 코드에 길목 ID가 없었던 지표는 비교 불가로 표시하고 영상 수동 검토로 보완한다.

### P2 — 경보 정보 전달

제안 `ShotContext`와 공유 정보 구조 추가. PlayerShooter → Target 최초 파괴 → Director까지 구현. NoiseSystem과 우선순위 충돌 정리.

완료: T01~T04, T06. 과녁/점수/포탈 회귀 확인. 경보 수신과 명령 발행 로그.

### P3 — 공용 설정·순찰·길목 데이터

제안 `MonsterDirectorSettings.cs`, `AITacticalMap.cs`. 기존 값을 이관하고 두 씬의 공통 설정 연결. 실제 NavMesh 위에서 순찰 경로와 gate를 배치한다. 지점별 도달 가능 검사 및 ID 중복 검사 제공.

완료: 5마리 순찰 순회, 연결 통로 통과, 각 길목 경로 유효성, 설정 asset 공유 확인.

### P4 — 차단·명령 수명·수색

MonsterDirector 후보·비용·배정 교체. MonsterAI 명령 종료·기절 복귀를 계약에 맞춘다. 과거 차단 경로를 동시에 켜두지 않는다. 기존 디버그 표시가 새 데이터와 일치하도록 수정한다.

완료: T05~T11. 후보 제외 이유와 명령 근거가 로그에 남음. 컴파일·관련 테스트 통과.

### P5 — 경험 지표·튜닝

자동 후보와 수동 annotation 연결. 기준선과 같은 조건으로 시나리오·자유 플레이 비교. 값은 한 축씩 변경. 최종 설정과 실패 사례를 남긴다.

완료: 표본수·분모 있는 비교표, 확인/불명확/제외 판정, 관찰 도구 성능 영향 확인. 평균 프레임 시간 또는 프로파일 결과를 관찰 켬/끔으로 비교하고 실제 수치 기록.

### P6 — 포트폴리오 촬영·문서 정리

아래 영상 구성으로 짧은 증거 클립 제작에 필요한 북마크·타임코드·설정을 정리한다. 사용자가 직접 녹화해야 하는 환경이면 녹화 절차와 재현 배치를 제공하고 촬영 완료라고 보고하지 않는다.

기존 설계 문서를 최종 구현과 일치시킨다. 폐기 기록은 역사로 구분하고 현재 동작 표와 섞지 않는다.

완료: 최종 설정, 검증표, 알려진 한계, 클립 목록/타임코드, 인계 메모.

## 11. 포트폴리오에서 보여줄 장면

추천 총 60~90초. 플레이 화면을 크게 두고 탑뷰는 판단을 설명하는 보조 화면으로 사용한다.

1. **문제 10초:** 변경 전 같은 복도에 겹친 몬스터. 실제 확보한 영상만 사용.
2. **과녁 경보 10~15초:** 과녁 파괴 → 탑뷰에 발사 위치 경보 → 한 개체 조사, 다른 개체 길목 이동. 자막은 '파괴 시 발사 위치 공유'.
3. **경로 변경 15~20초:** 정면/옆길 차단 몬스터가 실제 화면에 등장 → 플레이어가 다른 통로 선택. 같은 순간 탑뷰에 길목과 이동 궤적. 잠깐 정지 편집을 쓰면 '설명용 정지'라고 구분.
4. **시야 단절 10~15초:** 벽 뒤 반대 방향 이동 → AI 마지막 정보 마커 정지 → 몬스터는 다른 곳 수색. 실제 위치 마커와 알려진 위치 마커를 명확히 구분.
5. **기절 탈출 10~15초:** 출구 차단 개체 기절 → gate 통과 → 이어지는 탈출. 단순 명중 순간에서 영상을 끊지 않는다.
6. **검증 5~10초:** 테스트 조건·실행 수·확인 건수·남은 한계를 간단히 제시.

화면 자막은 '사실 → 결과' 순서로 작성한다. 예: '오른쪽 출구 선점 → 플레이어가 왼쪽 통로 선택'. 후보 자동 검출만 있는 장면에는 'AI 때문에 방향 전환'이라고 쓰지 않는다.

최종 슬라이드 예시(빈칸은 실측 후 입력):

| 검증 항목 | 변경 전 | 변경 후 | 근거 |
|---|---:|---:|---|
| 차단 노출 기회 | 미측정 | 미측정 | 화면 가시성 로그 + 영상 |
| 경로 변경 후보 / 수동 확인 | 미측정 | 미측정 | eventId·타임코드 |
| 시야 단절 / 추격 해제 | 미측정 | 미측정 | 별도 정의로 집계 |
| 기절 후 gate 통과 / 탈출 확인 | 미측정 | 미측정 | 자동 사건 + 영상 검토 |
| 최장 몬스터 화면 미노출 시간 | 미측정 | 미측정 | 동일 길이 자유 플레이 |

## 12. 최종 완료 체크리스트

- [ ] 코드와 씬이 컴파일되고 새 오류가 없다.
- [ ] 실제 플레이 위치는 목격·발사 context 외 경로로 AI에 유출되지 않는다.
- [ ] 과녁 경보는 중복되지 않고 일반 소음과 충돌하지 않는다.
- [ ] 5마리·추격 상한 2·기존 게임 규칙이 유지된다.
- [ ] 순찰·차단 데이터가 실제 맵과 연결되며 도달 불가 후보는 제외된다.
- [ ] 명령이 정당한 사유 없이 흔들리지 않고 기절·수색 실패·사냥 종료 시 정리된다.
- [ ] 관찰 화면은 같은 실행을 보여주고 게임 규칙을 변경하지 않는다.
- [ ] 기록 수치와 사람의 인과 해석이 분리돼 있다.
- [ ] 변경 전후 조건·시도 수·실패 사례가 남아 있다.
- [ ] T01~T14 결과에 통과·실패·미실행이 구분돼 있다.
- [ ] 촬영한 장면만 촬영 완료로 보고한다.
- [ ] 마지막 보고에 변경 파일·실제 검증·남은 한계·다음 재현 절차가 있다.
