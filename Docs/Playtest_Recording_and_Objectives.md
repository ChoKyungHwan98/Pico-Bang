# 직접 플레이 기록과 과녁·탈출구 검증

## 플레이 방법

1. `ShooterInGame` 씬에서 Unity Play를 누르고 게임의 Start 버튼을 누른다.
2. 평소처럼 플레이한다. 라운드 시작 시 자동으로 기록하며 별도 녹화 조작은 필요 없다.
3. 클리어, 게임 오버, 재시작 또는 Unity Play 정지 시 기록을 닫고 요약을 저장한다.
4. 플레이가 끝났다고 알려주면 최신 기록을 분석할 수 있다. 다른 라운드를 시작해도 이전 기록은 남는다.

Editor 저장 위치: `PlaytestRecordings/<날짜_시간_ID>/`. 빌드에서는 `Application.persistentDataPath/PlaytestRecordings`를 사용한다. 파일은 로컬 저장되며 Git에서는 제외한다.

- `trace.jsonl`: 시작 시 맵 NavMesh와 과녁 배치, 약 0.1초 간격의 플레이어·몬스터 위치/방향/속도/상태/목적지, 카메라 방향, 체력, 남은 시간. 현재 기록 스키마는 `pico-playtest-v2`다.
- 이벤트: 사격, 과녁 파괴, 몬스터 역할·상태 변경, 배정 경로, 기절, 피격, 복귀 순간이동, 포탈 개방·진입, 라운드 종료.
- `summary.json`: 이동 거리, 평면 이동 거리, 정지 시간, 순간이동 횟수와 종료 결과. 거리는 매 렌더 프레임 누적하고 순간이동은 제외한다.
- `latest-session.txt`: 가장 최근 기록 폴더. 자동 검증 기록에는 `automated_validation` 이벤트를 넣어 실제 플레이와 구별한다.

분석 명령: `python AgentScripts/analyze_playtest.py`. 특정 기록을 분석하려면 기록 폴더 경로를 마지막 인자로 넣는다. `analysis.json`과 전체 맵 위 이동 경로 `paths.svg`를 생성한다.

기록은 동영상이나 시선 추적이 아니다. 화면 내 몬스터 여부는 몸통의 한 점과 벽 차폐 검사로 추정한다. 경로 변경만으로 “몬스터를 보고 방향을 바꿨다”는 의도를 단정하지 않는다. 포트폴리오에 원인까지 보여주려면 실제 게임 화면 녹화와 해당 시간의 로그를 함께 사용한다. 프로세스 강제 종료 시 마지막 버퍼나 요약은 유실될 수 있으나, 이미 기록된 JSONL은 분석 가능하다.

## 이번 과녁 변경

- 벽 고정 배치를 유지한다. 낮음 1.1~1.65m 약 20%, 기본 2.1~2.8m 약 60%, 높음 3.4~4.2m 약 20%로 구성한다.
- 낮은 벽 등 배치가 어려운 곳은 기본 높이로 대체한다. 높이 비율보다 정상적인 배치와 라운드 완주 가능성을 우선한다.
- 과녁 전체를 지지하는 벽, 시작점에서 도달 가능한 사격 위치, 과녁까지의 시야, 과도하지 않은 조준 각도를 검사한다.
- 과녁 사이 평면 간격을 유지하여 같은 벽에 수직으로 몰리는 배치를 피한다. 지역별 배치 부족분은 다른 지역에서 보충한다.
- 기존 메인 씬의 과녁 수 150개와 목표 30개는 유지한다. 이동 중 빠르게 맞히는 과녁과 조금 더 조준해야 하는 과녁을 섞는 첫 단계다. 보상 차등이나 이동 과녁은 이번 범위에 포함하지 않는다.

다음 튜닝은 실제 기록을 본 뒤 결정한다. 과녁을 때리는 동안 몬스터가 너무 멀거나 한 구간에 과녁이 몰려 멈춰 쏘기만 한다면 높이를 더 올리기보다 교차로 전후의 배치 밀도와 구역별 분포를 조정한다.

## 고정 탈출구

- `GameFlowManager.PlayerStartPoint`의 X/Z에 항상 생성한다. 바닥 접지용 Y 보정만 허용한다. 라운드 재시작에도 위치를 바꾸지 않는다.
- 외부 에셋 없이 런타임 메시, 링, 자체 셰이더로 제작한다. 시작부터 잠긴 프레임이 보이고 목표 달성 시 청록색으로 활성화된다.
- 잠금 중 트리거는 비활성화한다. 목표를 달성한 뒤 시작점으로 돌아와 트리거에 들어가야 클리어된다.
- 과거 씬의 포탈 오브젝트는 비활성화하여 무작위 포탈과 중복 동작하지 않게 한다.

## 검증과 유지 조건

`AgentScripts/PlaytestPolishRegression.cs`의 `Validate`를 메인 씬 Play 모드에서 실행한다. 테스트는 자동 검증용이며 실제 플레이 체감의 증거가 아니다.

- 시드 1/2/3에서 과녁 150개 배치, 높은/낮은 과녁 혼합, 모든 사격 위치의 완전한 NavMesh 경로와 시야 확인.
- 세 번 재배치해도 포탈 시작점 고정, 잠긴 트리거 비활성화 확인.
- 목표 달성으로 개방되되 멀리 있는 플레이어는 클리어되지 않음, 실제 트리거 진입으로 클리어됨 확인.
- 10m 평면 이동 기록, 목표·기절·포탈 이벤트와 종료 요약 저장 확인.
- 일반 Start 버튼의 카운트다운 후 자동 기록 시작과 Unity Play 정지 후 요약 저장 확인. Editor 정지는 Unity의 `OnApplicationQuit` 콜백으로 `application_quit`으로 표시될 수 있다.
- 기존 몬스터 선발·협공·추격 배정 동작은 유지한다. 이번 AI 수정은 기록 이벤트 연결에 한정한다.

빌드 실행과 실제 사용자 플레이의 재미 평가는 별도로 필요하다. 녹화 영상 없이 경로 변경의 심리적 원인이나 정확한 화면 내용을 확정하지 않는다.
