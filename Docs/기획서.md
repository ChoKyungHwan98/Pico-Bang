## 0. 프로젝트 맥락

- **목적**: 포트폴리오
- **지망 직군**: 전투 기획자 / 시스템·콘텐츠 기획자
- **출발점**: 강의에서 배운 것은 **플레이어 조작부뿐**. 그 최소 기능 세트만으로 성립하는 게임을 만들어보자는 발상에서 시작.
- **자체 판단**: 완성물의 성격은 **레벨 디자인 + 전투 + 시스템**에 가깝다.

### 미해결 고민 (본인 제기)
"최소 기능으로 미니게임을 만들었다"고 설명하면 *강의 듣고 생각 없이 만든 결과물*로 읽힐 위험이 있다. 어떻게 어필할 것인가.

## 1. 코어 루프

빠르게 달리며 몬스터에게 쫓긴다
→ 랜덤 배치된 **과녁**을 파괴해 **스코어** 획득
→ 일정 수 파괴 시 **출구 개방**
→ 출구 통과 시 **게임 클리어**

**착안점**: 팩맨 (쫓기며 수집하는 구조)

### 핵심 체감
- 게임 속도는 **스피디**하게.
- **속도감**을 느끼게 하는 것이 포인트.

## 2. 전투 / 상호작용

### 좌클릭 — 이중 용도
| 대상 | 효과 |
|---|---|
| 과녁 | 파괴, 스코어 획득, 출구 개방 진행도 증가 |
| 몬스터 | **스턴** — 충돌 판정 일시 제한 + 이동 불가 |

### 리스크: 소리
- 좌클릭은 **소리를 발생**시킨다.
- 과녁을 부수면 소리가 나므로 **몬스터에게 들키기 쉬워진다**.
- → 진행에 필요한 행동이 곧 위험을 부르는 구조.

## 3. 몬스터 AI — 총 5마리

### 역할 분담
| 구분 | 수 | 행동 |
|---|---|---|
| **구역 몬스터** | 4 | 지정된 구역을 랜덤 이동하며 탐색 |
| **전역 몬스터** | 1 | 맵 전체를 수색하며 플레이어를 찾아다님 |

### 청각 범위 (비대칭)
- **전역 몬스터**: 소리를 듣는 범위가 **넓다**
- **구역 몬스터 4마리**: 전역 몬스터보다 **좁다**

### 발견 시 연쇄
1. 전역 몬스터가 플레이어를 발견
2. 맵에 흩어진 **구역 몬스터 4마리를 호출**
3. 4마리가 플레이어 위치를 **포위하듯 감싼다**

### 이동 제약
- 맵에 **단차가 있든 없든 무조건 추격 가능해야 한다.**

### 몬스터 행동 규칙 (2026-09-11 확정)

**구조: 두 개의 뇌** (참고작 에일리언: 아이솔레이션)
- 위쪽 뇌 = **전역 몬스터의 전두지휘**(감독). 플레이어 위치를 알지만 구역 몬스터에게는 흐린 지점만 준다.
- 아래쪽 뇌 = **구역 몬스터 4마리**. 전역 몬스터의 **눈먼 수족**이다. 4마리가 서로 다를 필요 없다.
  - 이유: 스스로 머리를 쓰지 않고 시킨 대로 움직여서 **읽히는 것**이 재미다. 소울라이크에서 가드만 하면 무조건 잡기를 쓰는 적이 재미없는 것처럼, 완벽히 대응하는 적은 재미가 없다.

**구역 몬스터의 흐름**
| 상황 | 행동 |
|---|---|
| 평상시 | 구역 순찰 |
| 감독에게 제보받음 / 소리를 들음 | 그 지점까지 **추격 속도로** 이동 → 주변 수색 |
| 플레이어를 직접 봄 | 추격 |
| 시야를 놓침 | 마지막으로 본 위치까지 추적 → 주변 수색 → 발견 실패 시 **구역 복귀** |
| 레이저에 맞음 | 기절 |

**지휘 규칙**
- 전역 몬스터가 제보하면 **제보 지점에서 가장 가까운 구역 몬스터 2마리**만 간다. 나머지 2마리는 구역 순찰 유지.
- **동시에 추격하는 건 최대 2마리.** 비엔나 소시지처럼 줄줄이 따라오는 것을 피한다.
  - 3마리 이상이 쫓게 되면 **전역 몬스터 1 + 가장 가까운 구역 몬스터 1**만 추격하고, 나머지는 **플레이어가 가려는 위치로 앞질러 가서 매복**한다.
  - (구현 방식, Claude) 매복 지점 = 플레이어 진행 방향 15m 앞(벽에 막히면 모퉁이 앞). 매복한 몬스터는 플레이어가 8m 안에 오면 덮치고, 그러면 가장 뒤처진 추격자가 대신 매복으로 빠진다 — 뒤따르던 놈과 앞에서 기다리던 놈이 역할을 교대.
- 복귀 속도는 미정 — 현재 순찰 속도.

### 테스트 도구
- **AI 테스트 씬** `Assets/Scenes/ShooterInGame_AITest.unity` — 본 씬의 복사본. 맵 전체를 위에서 한눈에 보며 몬스터 상태·시야·청각·목적지·파견·매복을 확인한다.
  - 조작은 최소한만: **WASD(지도 기준, W = 지도 위쪽) · Shift 달리기 · 좌클릭 = 플레이어 자리에서 소리(발사음 30m)**
  - 게임 화면·게임 UI·연출(달리기 속도선 등)은 모두 끈다. 무적·제한 시간 정지 자동.
  - (피드백) 처음엔 오른쪽 아래에 게임 화면 창을 두고 캐릭터 시점 기준으로 움직였는데, 지도와 방향이 달라 헷갈려서 뺐다.

### 설계 방침 (본인 명시)
팩맨을 그대로 옮기려 했으나 **구현이 어려웠고 의도대로 움직이지 않았다.**
→ 팩맨 모방이 아니라 **본인 기획이 들어가야 한다**고 판단.
→ 각 몬스터는 **고유 행동 패턴**을 가진다.

## 4. 레벨 / 맵

- 현재 **sample map 에셋** 사용 중.
- **미결**: 맵을 별도 제작해야 하는가?
  - 새로 만든다면 기존 맵의 메시·머티리얼을 쓰고 싶다(2026-09-11 본인 언급).
  - 참고(구현 측 확인): 기존 맵은 바닥·장애물·벽이 **통짜 메시 3개**라 부품 단위 재배치는 불가. 체크무늬 머티리얼을 입힌 블록으로 새로 쌓는 방식이 된다.

### 과녁 (2026-09-11 결정)

- **배치는 무작위**로 유지한다.
- 과녁은 **점수를 모으는 수집품**이다. 과녁 자체에 큰 의미를 부여하지 않는다 — **재미는 몬스터가 준다.**
- 벽에 붙은 과녁만 있는 건 재미없다 → 두 종류로:
  | 종류 | 형태 |
  |---|---|
  | 벽 과녁 | 지금처럼 벽에 붙은 원판 |
  | 공중 과녁 | 허공에 떠서 **위아래로 아주 조금씩 둥실거리는 구체** |
- 공중 과녁은 **동선을 방해하지 않게 머리 위**에 둔다 (테스트 피드백: 낮게 떠 있으면 달리는 길을 막음). 현재 바닥에서 3.2~4.5m — 점프해도 닿지 않는 높이
- **최종 (같은 날 번복): 과녁은 벽에만.** 공중 과녁은 3D에서 시야와 동선을 가린다.
  - 판단 근거: 팩맨의 "점 먹기"는 **맵 전체가 한눈에 보이는 2D**라서 길 한가운데 있어도 방해가 안 된다. 3인칭 3D에서는 몬스터를 먼저 발견하는 게 생존의 핵심인데 공중 물체가 그 시야를 가린다.
  - 과녁 역할은 **스코어링 + 클리어 조건**. "달려서 먹기"에 가까운 느낌이지만 동선을 막으면 안 된다(몬스터가 낑길 수 있음).
  - (포트폴리오 서사) 팩맨식 수집을 3D로 옮기려 했다 → 공중 과녁을 시험해 보니 시야·동선을 가렸다 → 2D라서 가능했던 구조임을 확인하고 벽 과녁으로 돌아왔다.
- **골고루 배치**: 무작위는 유지하되, 여러 곳을 돌아다니며 모으게 한다.
  - 걸을 수 있는 영역을 **3×3칸**으로 나눠 칸마다 같은 수. 벽 과녁은 눈높이(1~2.3m)에만.
  - ~~총 45개(칸당 5)~~ → 테스트 결과 **너무 적음**. "과녁이 많이 있고 그걸 쏘는 것"이 원하는 느낌.
  - 현재 **150개**(칸당 약 17), 포탈 개방 **30개**. 원래 씬 값 300개는 벽이 과녁으로 도배돼 중간값으로 잡음 — 플레이하며 조정.

### 포탈 (2026-09-11 결정)

- **무작위 구역**(A~D 중 하나)에 열린다.
- 단, **걸어서 닿을 수 있는 곳만**: 높이 올라간 곳, 조그만 발판 위, 점프로만 닿는 곳은 안 된다.
  - 구현 기준: 둘레 3m가 평평하게 트임(작은 발판·벽 틈 제외) / 점프 링크 없이 걸어서 가는 경로가 있음(점프로만 닿는 곳 제외)
  - "시작 지점과 높이가 비슷할 것"은 뺐다 — 구역 바닥 자체가 시작 지점보다 1~2m 높은 넓은 비탈이라 이 조건이면 구역 A·C에서 자리를 못 찾았다

### 맵 (2026-09-11 결정)

- **지금 맵을 그대로 쓴다.** 새 맵 구상(허브 + 네 구역 + 순환로, 대칭형)은 너무 반듯해서 구조가 한눈에 읽혀 기각. 지금 맵의 불규칙함(넓은 곳·좁은 곳·높낮이 섞임)이 오히려 쫓기는 게임에 맞다.
- 문제는 설정으로 고친다: 구역 반경(현재 70m로 서로 겹침), 포탈 위치, 과녁 쏠림. 막다른 길은 플레이해 보고 필요할 때만 블록 추가.
- 채택하지 않은 안 (Claude 제안 → 기각):
  - 미끼 과녁(몬스터 유인 도구) — 과녁을 몬스터 조종 수단으로 생각하지 않았음
  - 위험 과녁(몬스터 구역 안 고득점)
  - 연쇄 과녁(연속 파괴 보너스) — **좌클릭에 딜레이가 있어서** 연속 사격 구조와 맞지 않음

## 5. 미결 사항 — 기획 결정 필요

아래는 구두 설명에서 아직 정해지지 않은 항목. 구현 전에 값이 필요하다.

### 실패 조건
- 몬스터에게 잡히면 어떻게 되는가? 즉사 / 체력 감소 / 붙잡힘 상태?
  - (`PlayerHealth` 스크립트가 이미 존재 — 체력제를 전제했던 흔적)
- 실패 시 재시작 단위는? 라운드 전체 / 체크포인트?

### 수치
- 스턴 지속 시간
- 소리 전달 반경 (전역 / 구역 각각)
- 출구 개방에 필요한 과녁 파괴 수
- 몬스터 이동 속도 대 플레이어 이동 속도 비율 (속도감의 핵심)

### 행동 규칙
- 전역 몬스터의 **발견** 조건 — 시야인가 소리인가 둘 다인가?
- 포위 대형의 구체적 형태 — 등간격 원형? 퇴로 차단 우선?
- **추격 해제 조건** — 플레이어를 놓치면 원래 구역으로 복귀하는가? 얼마 후에?
- 호출된 구역 몬스터는 자기 구역을 벗어나는가?
- 스턴은 전역 몬스터에게도 통하는가?

### 스코어
- 스코어의 용도 — 단순 기록? 등급 판정? 클리어 조건과 별개인가?

## 6. 구현 메모 (Claude 담당 — 기획서에서는 생략 가능)

기존 코드에 관련 자산이 이미 존재:

- `MonsterAI` / `MonsterController` / `MonsterRole` — 역할 분담 구조가 이미 잡혀 있음
- `GridJumpLinker` + `NavMeshRoot` — **단차 추격**을 위한 NavMesh Link 처리로 추정
- `TargetManager` / `Target` — 과녁 관리 및 랜덤 배치
- `SpawnAreaGenerator` — 구역 기반 배치
- `GameFlowManager` — 게임 상태 전환 (인트로 / 인게임 / 클리어 / 오버)
- `PlayerShooter` / `PlayerHealth` — 사격 및 피격
- `SoundManager` — BGM/SFX
- 씬 오브젝트: `Zone_A` ~ `Zone_D` + `Zone_Global`, `Monster_A` ~ `Monster_D` + `Monster_Global`, `Escape_Portal`

→ 구역 4 + 전역 1 구조가 씬에 이미 반영되어 있음. 기획과 구현이 어긋난 부분을 먼저 대조할 것.
