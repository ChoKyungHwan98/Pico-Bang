## 0. 프로젝트 맥락

- **목적**: 포트폴리오
- **지망 직군**: 전투 기획자 / 시스템·콘텐츠 기획자
- **출발점**: 강의에서 배운 것은 **플레이어 조작부뿐**. 그 최소 기능 세트만으로 성립하는 게임을 만들어보자는 발상에서 시작.
- **자체 판단**: 완성물의 성격은 **레벨 디자인 + 전투 + 시스템**에 가깝다.

### 미해결 고민 (본인 제기)
"최소 기능으로 미니게임을 만들었다"고 설명하면 *강의 듣고 생각 없이 만든 결과물*로 읽힐 위험이 있다. 어떻게 어필할 것인가.

## 1. 코어 루프

빠르게 달리며 몬스터에게 쫓긴다
→ 랜덤 배치된 **과녁**을 파괴해 **스코어** 획득
→ 일정 수 파괴 시 **출구 개방**
→ 출구 통과 시 **게임 클리어**

**착안점**: 팩맨 (쫓기며 수집하는 구조)

### 핵심 체감
- 게임 속도는 **스피디**하게.
- **속도감**을 느끼게 하는 것이 포인트.

## 2. 전투 / 상호작용

### 좌클릭 — 이중 용도
| 대상 | 효과 |
|---|---|
| 과녁 | 파괴, 스코어 획득, 출구 개방 진행도 증가 |
| 몬스터 | **스턴** — 충돌 판정 일시 제한 + 이동 불가 |

### 리스크: 소리
- 좌클릭은 **소리를 발생**시킨다.
- 과녁을 부수면 소리가 나므로 **몬스터에게 들키기 쉬워진다**.
- → 진행에 필요한 행동이 곧 위험을 부르는 구조.

## 3. 몬스터 AI — 총 5마리

### 역할 분담
| 구분 | 수 | 행동 |
|---|---|---|
| **구역 몬스터** | 4 | 지정된 구역을 랜덤 이동하며 탐색 |
| **전역 몬스터** | 1 | 맵 전체를 수색하며 플레이어를 찾아다님 |

### 청각 범위 (비대칭)
- **전역 몬스터**: 소리를 듣는 범위가 **넓다**
- **구역 몬스터 4마리**: 전역 몬스터보다 **좁다**

### 발견 시 연쇄
1. 전역 몬스터가 플레이어를 발견
2. 맵에 흩어진 **구역 몬스터 4마리를 호출**
3. 4마리가 플레이어 위치를 **포위하듯 감싼다**

### 이동 제약
- 맵에 **단차가 있든 없든 무조건 추격 가능해야 한다.**

### 몬스터 AI 설계 (2026-09-12 확정 — 이전 2026-09-11 규칙을 대체)

> **설계 원칙: "플레이어를 잘 쫓는 AI"가 아니라 "플레이어가 갈 수 있는 안전한 길을 점점 줄이는 AI"를 만든다.**

**구조**
```
                [ Director ]
           보이지 않는 전체 조정자
                    │
     ┌──────────────┼──────────────┐
     ↓              ↓              ↓
 전역 몬스터      구역 몬스터 × 4
     └────── 각각 자기 FSM ──────┘
```
- **Director는 몬스터 한 마리가 아니다.** 전역 몬스터도 맵을 뛰어다니는 몬스터이고, Director는 뒤에서 몰리지 않게 조정하는 시스템.
- **구역 몬스터 4마리는 같은 AI/FSM.** Flanker/Blocker 같은 별도 Role 시스템은 만들지 않는다. 차이는 담당 구역과 현재 상황뿐.
- **전역 몬스터**도 기본 구조는 같고, 넓게 순찰하고 청각이 훨씬 좋다 ("찾아내기 쉬운 사냥개").
- Director → 기존 FSM에 **명령/목적지만 전달**.

**개별 몬스터 FSM (6상태)**
| 상태 | 행동 |
|---|---|
| 순찰 | 자기 영역 순찰 (전역은 넓게) |
| 이동/수색 | 소리 난 곳·마지막 목격 위치·Director가 준 수색 지점으로 **추격 속도로** 이동 → 주변 확인 |
| 추격 | 플레이어를 **직접 보고 있을 때** 현재 위치를 쫓음 |
| 복귀 | 수색·사냥이 끝나면 자기 영역으로 |
| 차단(Ambush) | 플레이어가 갈 것으로 예상되는 곳에 먼저 가서 대기 |
| 기절 | 레이저 피격 시 3초 |

**AI가 플레이어 위치를 어디까지 아는가 (가장 중요)**
- 보고 있을 때: 현재 위치를 안다 → 추격 가능.
- 놓친 순간부터: **진짜 현재 위치를 모른다.** 아는 것은 마지막 목격 위치 / 시간 / 이동 방향 / 누가 봤는가 뿐.
- 몬스터끼리(Director가) 공유하는 것도 실제 Player Transform이 아니라 이 정보뿐.
- **소리는 "플레이어가 여기 있다"가 아니라 "여기서 소리가 났다".** 과녁을 부수는 건 "여기 있다고 광고하는 위험한 행동"이지만, 벽 너머에서 자동으로 위치를 아는 불공정함은 없다.
- 플레이어가 예상과 반대로 도망치면 AI는 모른다 — **의도된 것.** 따돌렸다는 느낌을 만든다.

**Director 규칙**
- **전역이든 구역이든 발견하면 포위가 시작된다.** 강도는 **B안**: 구역 몬스터 발견 → 작은 포위 / 전역 몬스터 발견 → 큰 포위.
- **직접 추격자는 최대 2마리**(테스트값). 중요한 건 숫자가 아니라 **"모든 몬스터가 추격에 들어가지 않는다"**.
- 나머지는 **다른 위치로 이동·수색·차단**해 공간을 좁힌다. 차단 몬스터는 플레이어에게 직선으로 달려갈 필요가 없다 — 그 자리에 있기만 해도 플레이어가 "저쪽은 위험하네" 하고 **경로를 바꾸면 성공**.
- **놓쳤을 때 수색 지점을 분산**한다. 한 점에 뭉치지 않고, 마지막 이동 방향 쪽을 좀 더 의심.
- **차단도 마지막으로 본 방향 기준으로 앞길을 예상.** 예상대로 오면 "젠장 앞에 있다", 방향을 틀었으면 "운 좋게 빠져나왔다" — 둘 다 재미있는 결과.
- 일정 시간 못 찾으면 **사냥 종료** → 복귀 → 순찰. 플레이어가 **실제로 따돌릴 수 있어야** 한다.

**목표 장면**
> 과녁을 부숨 → 소리를 듣고 몬스터가 움직임 → 구역 몬스터에게 발견 → 한 마리가 뒤에서 추격, Director가 다른 몬스터를 앞길로 → "왼쪽은 몬스터가 들어오네" → 오른쪽으로 방향 변경 → 앞쪽에도 접근 → 시야를 끊음 → AI는 마지막으로 본 방향을 수색 → 플레이어는 반대로 빠져나감 → 사냥 종료 → "좋아, 다음 과녁."

**구현 수치 (Claude 초기값, 테스트하며 조정 — 전역 몬스터 인스펙터 "6. 조정자")**
| 항목 | 값 |
|---|---|
| 최대 직접 추격 | 2 |
| 작은 포위 차단 수 / 큰 포위 차단 수 | 1 (앞길) / 2 (앞-왼쪽·앞-오른쪽) |
| 앞길 거리 / 옆길 | 목격 위치 + 방향 × 15m / 방향 × 10m ± 옆 12m |
| 놓침 판정 / 사냥 유지 | 목격이 0.5초 끊기면 수색 분산 / 마지막 목격 후 8초 |
| 수색 분산 | 마지막 목격 위치 + 방향 쪽 부채꼴 8~18m |
| 차단 대기 중 덮침 | 8m |
- 복귀 속도는 미정 — 현재 순찰 속도.

**2026-09-14 결정 (AI 테스트 씬 스크린샷 검토)**
- **길목을 사람이 지정하지 않는다.** 폴리싱 계획서(`몬스터AI_폴리싱_실행계획.md`)의 "지정 길목·지정 순찰로"는 과하다고 판단. 지금의 8방향 자동 후보 방식을 유지한다.
- 좋았던 점: 차단 몬스터가 "플레이어가 그쪽으로 가면 도착할 즈음 만나는" 위치로 가는 장면.
- **문제: 사냥 중 몬스터 여러 마리가 모여 한 줄로 따라간다.** → 막는다.
- **추적 속도를 낮춘다.** "추적" = 플레이어를 **보지 못한 채** 움직이는 경우(놓친 위치로 가기·수색 지점·차단 지점). 보고 있을 때만 전속력.

| 항목 | 값 (Claude 초기값, 테스트하며 조정) |
|---|---|
| 추적 속도 | **현재 코드값: 추격 속도 × 1.0 (= 줄이지 않음).** 처음 0.75로 넣었으나 이후 작업(Codex)에서 "포위가 너무 늦어진다"는 이유로 1.0으로 되돌림 — **기획 확인 필요** |
| 차단: 플레이어보다 늦는 한도 | 3초 넘게 늦으면 안 보냄 |
| 차단: 다른 몬스터 길과 겹침 한도 | 50% 넘게 겹치면 안 보냄 |
| 줄줄이 감지 | 사냥 중 추격·차단 몬스터가 같은 방향 몬스터 바로 뒤 7m 안에 1초 이상 → 뒤쪽을 다른 빈 길로 (빈 길 없으면 그대로). 순찰·수색 중인 몬스터는 건드리지 않음 |
| 과녁 경보 | 과녁을 부수면 **쏜 순간의 플레이어 위치**가 무리에 공유됨 → 가장 가까운 1마리 조사 + 작은 차단 |

### 몬스터 AI 재설계 (2026-09-14 확정 — 위 규칙들을 대체)

**테스트 피드백 (AI 테스트 씬 스크린샷 3장)**
- 추적·두 개의 뇌·미리 가서 대기(차단)가 **체감되지 않는다.** 추적 성능이 부족하다.
- 한 마리가 쫓아도 다른 몬스터가 신호를 받지 않는다.
- 모퉁이를 돌면 곧바로 수색해 버린다.
- 소리가 몬스터의 주의를 끈다는 느낌이 없다.
- 원하는 장면: 남쪽으로 도망치면 남쪽 구역 몬스터가 앞길로 올라온다(2번). 전역 몬스터에게 들키면 여러 구역에서 각자 자기 방향으로 조여 온다(3번).

**핵심 전제: 숨기는 없다. 오로지 달려서 피한다.** 목표는 "들키지 않기"가 아니라 "포위망이 닫히기 전에 빠져나가기".

| 항목 | 결정 |
|---|---|
| 두 개의 뇌 | **감독은 진짜 위치를 안다.** 몬스터에게는 **흐린 목적지만** 내려보낸다(한 방향). 몬스터는 자기 눈에 보일 때만 정확한 위치로 쫓는다 — 컨닝 금지 |
| 반응 인원 | 누가 발견하든 **발견자 포함 3마리**. 발견자가 쫓고 2마리가 막는다. "4군데 중 3군데를 막고 1군데를 연다" |
| 막는 몬스터 | 뒤를 따라가지 않고 **내가 향하는 쪽을 각자 다른 길로 돌아서** 막는다. 도망친 쪽에 더 가까운 몬스터가 생기면 교대 |
| 추적(모퉁이) | 놓쳐도 곧바로 수색하지 않는다. **끈질김 6초** 동안 감독의 흐린 힌트로 계속 쫓는다. 다시 보면 채워지고, **놓칠 때마다 줄어든다**(6 → 4.2 → 2.9 … 최소 2초). 다 떨어지면 2초 두리번 → 복귀 |
| 속도 (A안) | 사냥 중 **거리에 따라**: 가까우면 10(플레이어 11보다 약간 느림), 멀면 최대 14. 똑바로 달리면 떨칠 수 있지만 먼 몬스터는 금방 따라붙는다. 플레이어 속도는 그대로 |
| 구역 이탈 | 사냥 중엔 구역을 꽤 벗어나도 된다. **복귀는 매우 빠르게(16)** |
| 소리 | 발사음 30m → **50m**, 구역 몬스터 청각 22.5m → **45m**. 들으면 **0.5초 멈칫하며 소리 쪽으로 몸을 돌린 뒤** 달려간다. 한 소리에 가까운 **2마리**까지 반응 |
| 줄줄이 | 계속 금지. 직접 추격 최대 2마리 |
| 정보 끊김 (A안, 2026-09-15 QA 후) | 아무도 못 보고 **추격자가 모두 포기하는 순간 감독도 진짜 위치를 알려주지 않는다.** 막는 팀원은 마지막으로 받은 곳을 확인하고, 사냥 종료(마지막 목격 8초 후)와 함께 돌아간다. 끝까지 달리면 떨칠 수 있다 |

- 이전 원칙 "감독도 진짜 위치를 모른다(2026-09-12)"는 이 결정으로 대체. 숨는 게임이 아니므로 공정성보다 **추격의 압박감**을 우선한다.

> (이전 방식 폐기 기록) 2026-09-11 구현은 전역 몬스터만 제보하고, 감독이 **플레이어의 진짜 위치**를 계속 읽어 주변으로 파견했다. 놓친 뒤에도 따라오고, 구역 몬스터 발견 시 포위가 없고, 놓치면 한 점에 뭉쳤다. → 위 설계로 교체.

  - (2026-09-15 피드백) 단차 때문에 이동이 막혀 테스트가 어려웠다 → **테스트 씬에서는 단차가 없어야 한다.**
    - 바닥을 "가장 가까운 걸을 수 있는 곳" 대신 위에서 아래로 광선을 쏴서 찾게 바꿈.

  - 게임 화면·게임 UI·연출(달리기 속도선 등)은 모두 끈다. 무적·제한 시간 정지 자동.
  - (피드백) 처음엔 오른쪽 아래에 게임 화면 창을 두고 캐릭터 시점 기준으로 움직였는데, 지도와 방향이 달라 헷갈려서 뺐다.

### 설계 방침 (본인 명시)
팩맨을 그대로 옮기려 했으나 **구현이 어려웠고 의도대로 움직이지 않았다.**
→ 팩맨 모방이 아니라 **본인 기획이 들어가야 한다**고 판단.
→ 각 몬스터는 **고유 행동 패턴**을 가진다.

### 과녁 (2026-09-11 결정)

- **배치는 무작위**로 유지한다.
- 과녁은 **점수를 모으는 수집품**이다. 과녁 자체에 큰 의미를 부여하지 않는다 — **재미는 몬스터가 준다.**
- 벽에 붙은 과녁만 있는 건 재미없다 → 두 종류로:
  | 종류 | 형태 |
  |---|---|
  | 벽 과녁 | 지금처럼 벽에 붙은 원판 |
  | 공중 과녁 | 허공에 떠서 **위아래로 아주 조금씩 둥실거리는 구체** |
- 공중 과녁은 **동선을 방해하지 않게 머리 위**에 둔다 (테스트 피드백: 낮게 떠 있으면 달리는 길을 막음). 현재 바닥에서 3.2~4.5m — 점프해도 닿지 않는 높이
- **최종 (같은 날 번복): 과녁은 벽에만.** 공중 과녁은 3D에서 시야와 동선을 가린다.
  - 판단 근거: 팩맨의 "점 먹기"는 **맵 전체가 한눈에 보이는 2D**라서 길 한가운데 있어도 방해가 안 된다. 3인칭 3D에서는 몬스터를 먼저 발견하는 게 생존의 핵심인데 공중 물체가 그 시야를 가린다.
  - 과녁 역할은 **스코어링 + 클리어 조건**. "달려서 먹기"에 가까운 느낌이지만 동선을 막으면 안 된다(몬스터가 낑길 수 있음).
  - (포트폴리오 서사) 팩맨식 수집을 3D로 옮기려 했다 → 공중 과녁을 시험해 보니 시야·동선을 가렸다 → 2D라서 가능했던 구조임을 확인하고 벽 과녁으로 돌아왔다.
- **골고루 배치**: 무작위는 유지하되, 여러 곳을 돌아다니며 모으게 한다.
  - 걸을 수 있는 영역을 **3×3칸**으로 나눠 칸마다 같은 수. 벽 과녁은 눈높이(1~2.3m)에만.
  - ~~총 45개(칸당 5)~~ → 테스트 결과 **너무 적음**. "과녁이 많이 있고 그걸 쏘는 것"이 원하는 느낌.
  - 현재 **150개**(칸당 약 17), 포탈 개방 **30개**. 원래 씬 값 300개는 벽이 과녁으로 도배돼 중간값으로 잡음 — 플레이하며 조정.

### 포탈 (2026-09-11 결정)

- **무작위 구역**(A~D 중 하나)에 열린다.
- 단, **걸어서 닿을 수 있는 곳만**: 높이 올라간 곳, 조그만 발판 위, 점프로만 닿는 곳은 안 된다.
  - 구현 기준: 둘레 3m가 평평하게 트임(작은 발판·벽 틈 제외) / 점프 링크 없이 걸어서 가는 경로가 있음(점프로만 닿는 곳 제외)
  - "시작 지점과 높이가 비슷할 것"은 뺐다 — 구역 바닥 자체가 시작 지점보다 1~2m 높은 넓은 비탈이라 이 조건이면 구역 A·C에서 자리를 못 찾았다

### 맵 (2026-09-11 결정)

- **지금 맵을 그대로 쓴다.** 새 맵 구상(허브 + 네 구역 + 순환로, 대칭형)은 너무 반듯해서 구조가 한눈에 읽혀 기각. 지금 맵의 불규칙함(넓은 곳·좁은 곳·높낮이 섞임)이 오히려 쫓기는 게임에 맞다.
- 문제는 설정으로 고친다: 구역 반경(현재 70m로 서로 겹침), 포탈 위치, 과녁 쏠림. 막다른 길은 플레이해 보고 필요할 때만 블록 추가.
- 채택하지 않은 안 (Claude 제안 → 기각):
  - 미끼 과녁(몬스터 유인 도구) — 과녁을 몬스터 조종 수단으로 생각하지 않았음
  - 위험 과녁(몬스터 구역 안 고득점)
  - 연쇄 과녁(연속 파괴 보너스) — **좌클릭에 딜레이가 있어서** 연속 사격 구조와 맞지 않음

## 5. 미결 사항 — 기획 결정 필요

아래는 구두 설명에서 아직 정해지지 않은 항목. 구현 전에 값이 필요하다.

### 실패 조건
- 몬스터에게 잡히면 어떻게 되는가? 즉사 / 체력 감소 / 붙잡힘 상태?
  - (`PlayerHealth` 스크립트가 이미 존재 — 체력제를 전제했던 흔적)
- 실패 시 재시작 단위는? 라운드 전체 / 체크포인트?

### 수치
- 스턴 지속 시간
- 소리 전달 반경 (전역 / 구역 각각)
- 출구 개방에 필요한 과녁 파괴 수
- 몬스터 이동 속도 대 플레이어 이동 속도 비율 (속도감의 핵심)

### 행동 규칙
- 전역 몬스터의 **발견** 조건 — 시야인가 소리인가 둘 다인가?
- 포위 대형의 구체적 형태 — 등간격 원형? 퇴로 차단 우선?
- **추격 해제 조건** — 플레이어를 놓치면 원래 구역으로 복귀하는가? 얼마 후에?
- 호출된 구역 몬스터는 자기 구역을 벗어나는가?
- 스턴은 전역 몬스터에게도 통하는가?

### 스코어
- 스코어의 용도 — 단순 기록? 등급 판정? 클리어 조건과 별개인가?
