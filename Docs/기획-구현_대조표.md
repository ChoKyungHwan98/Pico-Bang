## 1. 소리 시스템이 통째로 없다 ★최우선

기획의 핵심인 **"진행하려면 소리를 내야 하고, 소리를 내면 잡힌다"**가 게임에 존재하지 않는다.

- `MonsterAI.OnHearShooting()` — **정의만 있고 호출하는 곳이 단 한 군데도 없다.**
- `PlayerShooter.ShootLightning()`은 사격 시 몬스터에게 아무것도 알리지 않는다.
  - 알리는 것: 맞은 대상에게 직접 `OnHitByLaser` / `Target.OnHit` — **명중한 개체에만**
- 즉 현재 게임에서 **사격은 아무 위험도 만들지 않는다.** 리스크 없는 리워드.

추가로, 설령 호출되더라도 동작하지 않는다:

```csharp
// MonsterAI.cs:198
if (role != MonsterRole.Global_Stalker || currentState == State.Chase || isStunned) return;
```

**구역 몬스터는 아예 걸러진다.** 기획의 "4마리는 좁은 범위로 듣는다"가 "4마리는 못 듣는다"로 구현돼 있다.

### 필요한 것
- `PlayerShooter` → 사격 시 소리 발생 통지
- 역할별 청각 반경 분리 (전역 = 넓게 / 구역 = 좁게)
- **미결(기획)**: 과녁을 맞혔을 때와 빗맞았을 때 소리 크기가 같은가? 몬스터를 맞혔을 때는?

## 2. 포위가 유지되지 않는다

```csharp
// MonsterAI.cs:548  AlertNearbyMonsters
```

**현재 동작**: 호출 시점에 플레이어 기준 전/후/좌/우 4개 좌표를 **한 번** 계산 → 각 몬스터에게 전달 → 받은 몬스터는 `Investigate` 상태로 그 지점까지 이동 → 도착 후 **3초 두리번거리다 `Patrol`로 복귀**.

**기획 의도**: 플레이어를 "포위하듯 감싼다" — 즉 플레이어가 움직이면 **따라붙으며 유지되는 대형**.

차이: 지금은 *과거 위치로 한 번 달려가는 것*이지 포위가 아니다. 플레이어가 이동하면 대형이 즉시 무의미해진다.

### 슬롯 배정도 문제
```csharp
array[num2 % 4]   // 리스트 순서대로 배정
```
거리·경로를 고려하지 않아 **가장 먼 몬스터가 가장 가까운 자리를 받을 수 있다.** 서로 경로가 교차한다.

### 미결(기획)
- 포위 반경은? (현재 하드코딩 10m)
- 포위는 언제 풀리는가? 시간? 시야 상실? 거리?
- 포위 중에도 플레이어에게 돌진하는가, 거리를 유지하는가?

## 3. 몬스터별 "고유 행동 패턴"이 사실상 없다

`ChaseStyle` 4종이 선언돼 있으나 실제 차이가 거의 없다.

| 스타일 | 실제 코드 | 평가 |
|---|---|---|
| `Blinky_Direct` | 플레이어 위치 그대로 | 기본값과 동일 |
| `Pinky_Predict` | `target + playerVelocity * 0.5f` | ✅ 유일하게 의미 있음 |
| `Inky_Tactical` | `target + transform.right * 2f` | ❌ **자기 기준 2m 옆** — 측면 포위가 아니라 그냥 살짝 빗겨감 |
| `Rusher_Berserk` | 12m 이내 접근 시 3초간 속도 1.5배 | ✅ 동작함 |

기획서에는 "각각의 몬스터는 고유의 행동 패턴을 가진다"고 되어 있으나, 플레이 중 **체감상 구별되지 않을 것**이다.

### 미결(기획)
4마리를 어떻게 차별화할 것인가. 팩맨식(직진/예측/협공/변덕)을 유지할지, 본인 기획으로 새로 짤지.
→ 기획서 3장의 "팩맨 그대로 하지 말고 내 기획이 들어가야 한다"와 직결되는 항목.

## 4. 튜닝 값이 코드에 박혀 있다 ★포트폴리오 관점 중요

전투 기획자 포트폴리오라면 **모든 밸런스 수치가 인스펙터에 노출돼 있어야** 한다. 현재 하드코딩된 것들:

| 값 | 위치 | 내용 |
|---|---|---|
| 스턴 지속 | `MonsterAI.cs:309, 323` | 1.5초 + 1.5초 = 3초 |
| 호출 쿨다운 | `:386` | 2초 |
| 포위 반경 | `:550` | 10m |
| 수색 두리번 시간 | `:504` | 3초 |
| 광폭화 지속 | `:641` | 3초 |
| 광폭화 배율 | `:639` | 1.5배 |
| 점프 시간/높이 | `:660-661` | 0.5초 / 1.5m |
| 가속도 | `:163, 253, 258, ...` | 30/50/60/80/120 산재 |

### 죽은 필드
```csharp
public float contactDamage = 10f;   // :77 — 선언만 되고 어디서도 사용되지 않음
```
실제 접촉 데미지는 `PlayerHealth.TakeDamage(position)` 내부에서 결정된다. **인스펙터에서 이 값을 만져도 아무 일도 일어나지 않는다.** 튜닝하려다 혼란을 부르는 함정.

## 5. 잘 되어 있는 것 (유지)

- **시야 판정** — 거리 + FOV 각도 + `Physics.Linecast` 차폐까지 3단 검사 (`:524`)
- **기억 시스템** — `memoryTime` 동안 마지막 목격 지점 추적 후 `Investigate` 전환
- **단차 추격** — `agent.isOnOffMeshLink` 감지 → 포물선 점프 코루틴 (`:652`)
- **상태 복원** — `ResetMonster()`가 위치·회전·애니메이터까지 되돌림. 재시작 처리가 깔끔
- **Gizmo 디버그** — 시야/청각 반경 시각화 (`:690`). 기획 튜닝에 유용하니 살릴 것
- **게임 상태 연동** — `GameFlowManager.IsGameRunning`으로 일시정지 처리
